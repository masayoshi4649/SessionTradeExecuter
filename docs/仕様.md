# SessionTradeExecuterの仕様

日経3商品の標準は日中`NK225_D164_15`、米国開始15分前まで`NK225_P164_06`、前後15分の静観、開始15分後から`NK225_U165_03`です。TOPIXは日中T06・夜間T04を維持します。 詳細は[新標準手法](新標準手法.md)を参照してください。

判断には日経225・TOPIXのラージ板、約定と所有管理には選択した実商品を使います。画面損益と1場1行CSVは[セッション損益](セッション損益.md)、自動切替は[時間帯切替](時間帯切替.md)を参照してください。

## 設定と起動

配布先は `dist/{windows-amd64またはlinux-amd64}/SessionTradeExecuter/` です。Windowsは `session-trade-executer.exe`、Linuxは `./session-trade-executer` を引数なしで起動します。ポート既定は8090で、全インターフェースから接続できます。全5商品を一つの実行ファイルで扱い、商品ごとの単品配布は行いません。

| 発注商品 | 新規配布の片方向上限 | 日中標準 | 夜間標準 |
|---|---:|---|---|
| `NK225` | 2枚 | NK225_D164_15 | NK225_P164_06 → 静観 → NK225_U165_03 |
| `NK225mini` | 10枚 | NK225_D164_15 | NK225_P164_06 → 静観 → NK225_U165_03 |
| `NK225micro` | 20枚 | NK225_D164_15 | NK225_P164_06 → 静観 → NK225_U165_03 |
| `TOPIX` | 2枚 | TOPIX_T06 | TOPIX_T04 |
| `TOPIXmini` | 10枚 | TOPIX_T06 | TOPIX_T04 |

初期設定は全商品 `mode="off"` です。仮想は `dryrun`、実注文は `live` を商品ごとに指定します。画面のONは `live` を意味します。Qtyは今回の運転が所有する同方向の実玉と未約定新規の合算上限です。手動玉・前起動の管理外の玉は含めません。

読み込み先は実行ファイル隣の `conf/*.toml` です。作業ディレクトリには依存せず、設定がなければ終了します。`conf/settings.toml` が配布設定、画面保存の `conf/web-ui.toml` が公開設定の優先値です。`.toml.sample` は実行時に読みません。同じテーブルを複数の通常TOMLへ重複定義しないでください。

商品オプションはOFF・注文照合完了後だけ変更できます。稼働中はREST APIも拒否します。保存したモードは再起動にも適用します。元の設定、利用者が変更した実ルール、台帳、ログは通常の再配布で上書きしません。

旧標準のS01・P05・静観・D07の4枠と新旧の標準式が一致する日経商品だけを新3手法へ移行します。独自時間枠・数量・モード・接続先・改変式は保持します。移行版`settings_version=2`は通常保存で記録し、その後の明示的な旧手法選択を再移行しません。読込だけで元ファイルは書き換えません。

設定の抜粋です。商品・時間帯は全5商品分を保持し、通常は画面から編集してください。

```toml
# 標準設定の移行版。アプリが管理します。
settings_version = 2

[rule_engine]
# 実ルール12個の保存先。
directory = "conf/rules"

[startup]
action = "run"

[web]
host = "0.0.0.0"
port = 8090

[controller]
base_url = "http://10.10.100.1:8080"

[[instruments]]
product = "NK225mini"
mode = "off"
max_per_side = 10
day = "NK225_D164_15"
night = "NK225_U165_03"
# この商品のwindowsへ日中D164_15・米国前P164_06・静観・米国後U165_03の4枠を指定します。
```

[時間帯の完全な設定例](時間帯切替.md#tomlとrest)を参照してください。商品名から実行IDを自動生成するため、Web版に `trading.instance_id` や単品版の `[market]`・`[methods]` を追加しません。

| `startup.action` | 動作 |
|---|---|
| `"run"` | Web画面と商品別運転 |
| `"check"` | 全商品の設定検査だけで終了。通信なし |
| `"probe"` | 読み取りAPI・受信接続の検査だけで終了 |
| `"diagnostics"` | 保存済み資料から転送用の診断ZIPを出力。注文・API接続なし |

診断は `[startup]` に `action="diagnostics"` と `diagnostic_session="2026-10-26_Day"` を指定します。セッションの省略・空文字は最新の記録場です。通常運転へ戻す際は `action="run"` とし、`diagnostic_session` を削除または空文字に戻します。[診断データの出力](診断データの出力.md)を参照してください。

DryRunは注文・取消を送信せず、発注商品の新鮮な最良気配で仮想約定します。ONはcontrollerの生API転送へ実注文を送信します。銘柄ID・限月・立会時刻はcontrollerから取得し、設定へ再定義しません。

## 時刻と手法ID

時計は日本時間です。海外イベントに連動する項目は冬時間を基準にし、夏時間をアプリが自動補正します。

```toml
[schedule]
force_close_before_seconds = 600
day_extra_jst = "12:30"
us_open_jst = "23:30"
us_extra_delay_minutes = 30
london_extra_jst = "01:30"
```

米国開始は冬23:30・夏22:30、ロンドン連動は冬翌01:30・夏翌00:30です。両地域の夏時間は個別判定します。日経の後半補完は米国開始30分後です。S01は日中専用、P05は米国開始15分前までの夜間枠専用です。

| 手法ID | 選択範囲 | 内容 |
|---|---|---|
| `NK225_D164_15` | 日経・日中 | 支持別数量・失速待機・利益残玉保護・追撃確認 |
| `NK225_P164_06` | 日経・米国前の夜間枠 | 少量初回・利益残玉保護と追撃玉の逆行返済 |
| `NK225_U165_03` | 日経・米国後の夜間枠 | 反対板による初回待機と自方向の帯確認 |
| `NK225_S01` | 日経・日中 | D07の波担当に親利益保護・異親の後追い抑制 |
| `NK225_P05` | 日経・米国前の夜間枠 | 仮想B04入口から実玉の利益だけを追尾 |
| `NK225_D07` | 日経・昼夜 | 利益の分割回収と再参加 |
| `NK225_TG04` / `NK225_PG04` | 日経・昼夜 | 三担当／二担当の従来手法 |
| `NK225_T06` / `TOPIX_T06` | 各市場・日中 | 二市場追従と未参加補完 |
| `TOPIX_T04` | TOPIX・夜間 | 二市場の進行確認と補完 |
| `NK225_U06` | 日経・夜間 | 押戻り再進行と幅に応じた補完 |

条件式は計12個の[Exprルール](ルールエンジン.md)へ分離しています。未実装ID・市場や昼夜の組合せ違い・不正な式は起動前に拒否します。D07/S01は基本・追加・波担当へ10枚を5:3:2で配分します。少枚数では担当が0枚になったり部分返済できなかったりするため、10枚研究の単純倍率にはなりません。

旧現地時計 `us_open`・`london_extra` は互換用です。新しい `_jst` キーへ名前だけを変えず、時差を換算してください。同じ時計の新旧キー併記は拒否します。旧単品設定の移行記録は後掲の履歴であり、Web版に旧 `[algorithm]` 等を追加する手順ではありません。

## 注文と所有の分離

実注文はcontrollerの生KabuStation API転送へ送り、トレーリングや担当の切替はアプリ側で計算します。注文受付を約定とは見なさず、上流の明細で確認した数量だけを建玉へ反映します。

毎回の起動で新しいランダムな注文名前空間（Namespace）を作り、SQLiteへ保存します。表示用の `instance_id` や戦略の判断IDだけで所有を決めず、上流の `OrderID`・`ExecutionID`・`HoldID` と対応付けます。自動返済するのは、今回の起動で所有を確認した担当建玉だけです。似た時刻・価格・数量の他注文を推測で採用しません。

**再起動も新規運転として、建玉・候補・残玉予算を空から始めます。** 実注文では、前回の台帳に所有を記録した未確定注文・条件予約だけを取り消し、約定競合と終了を照合してから開始します。取消受付だけでは開始せず、結果不明や照合未完了なら停止します。他媒体の注文は取り消しません。前回の実建玉は返済せず手動管理へ移し、今回の自動返済と枚数上限から外します。例えば旧建玉1枚があっても、新上限10枚で新たに10枚を持ち、口座全体が11枚になることがあります。

仮想運転でも旧仮想玉や送信待ちを引き継がず、架空の清算約定は追加しません。旧状態は監査用に退避し、旧約定履歴を保持したまま、新状態へ同じSQLiteトランザクション内で切り替えます。枚数・手法を変更して再起動できます。同じ商品・モードの正本を使い、旧未確定注文を見失わないようにします。

同一OSユーザー・同一一時領域・同じcontroller URL・同じ商品・同じモードの組合せは排他します。共通の一時領域にOSロックを置くため、保存先や `instance_id` を変えても二重運転できません。TOPIXミニと日経マイクロは商品が異なるため同時運転できます。

この排他は異なるOSユーザー・ホスト・一時領域や、同じcontrollerを指す別URL間では共有できません。そのような構成では同一商品を重複運転しないでください。状態DBの複製から同時運転を始めることも避け、再起動には元のDBを引き継ぎます。

## 保存先

相対保存先は実行ファイルのフォルダが基準です。SQLiteは商品名の小文字とモードで分離し、終了CSVは共通ログ先の商品フォルダへ保存します。TOPIXミニの仮想運転例です。

| 配布フォルダからの相対パス | 内容 |
|---|---|
| `data/dryrun/topixmini/market.sqlite` | 二市場の原板・判断材料・運転状態 |
| `data/dryrun/topixmini/TOPIXmini.sqlite` | 約定履歴・監査記録・今回の注文と所有玉 |
| `log/TOPIXmini/2026-10-28_Day_dryrun.csv` | 終了確定後の6列約定履歴 |
| `log/sessionPL.csv` | 商品・モード別に1セッション1行の粗利益・粗損失・収支・新規合計枚数 |
| `log/web/操作.jsonl` | 画面の設定・モード変更 |
| `log/diagnostics/` | 明示操作で生成する診断ZIP |

実運転のSQLiteは `live` に分離し、終了CSVのファイル名には `_dryrun` を付けません。注文・約定・所有ID・判断根拠はSQLiteを正本とし、終了CSVの出力障害を約定取消しとして扱いません。売買管理カードの収支は手数料後です。

終了レポートは`log/{商品}/{セッション}.csv`（仮想は`_dryrun.csv`）と`log/sessionPL.csv`です。確認済み約定と管理外移管は、別途[Viewer用JSONL](Viewer連携.md)へ最小出力します。「セッション損益」タブは後者のCSVだけを読み、金額は手数料前です。削除された終了レポートをSQLiteから復活させません。[集計の定義](セッション損益.md)を参照してください。

旧モード別の詳細CSV・約定JSONL・`session_summary*.csv`と、`trace.jsonl`の自動出力・起動時再生成は行いません。既存の旧ファイルは自動削除しません。最新状態と原板はSQLiteに保持し、更新イベントは状態の版・大きさ・指紋を記録します。転送には明示操作で、対象場の全約定と診断要約を含む8MiB以下の分割ZIPを作れます。

商品ごとにフォルダやexeを複製する必要はありません。同じWeb画面で必要な商品だけを有効にし、既存の `data`・`log` を維持します。

## 旧単品版の移行記録（現在のWeb版では使用しない）

以下は廃止した単品版について残している履歴です。現在のWeb版へ旧単品台帳を自動移行する手順ではありません。

以下は、実行ID別の台帳になる前の旧版から引き継ぐ場合の手順です。既に商品別フォルダで運転している場合は、この移行を再実行せず、同じ実設定・実行ID・DBを使います。

互換の単品構成では、複数商品の旧設定を一つのworkerへまとめる指定を拒否します。旧プロセスを停止し、旧設定フォルダを内容を変えず `conf-legacy` として退避します。旧設定は、接続先・数量・戦略条件が保存時と一致するか検査するために必要です。対象商品の新フォルダの売買条件を旧設定に合わせ、`conf/settings.toml` を移行指定にします。

```toml
[startup]
action = "migrate_legacy"
duration_seconds = 0
legacy_conf = "conf-legacy"
```

`legacy_conf` は旧設定フォルダのパスです。相対パスは新しい実行ファイルのフォルダが基準で、絶対パスも指定できます。各商品の実行ファイルを引数なしで起動し、移行が完了したら `action="run"`・`legacy_conf=""` に戻して起動します。

移行は旧設定から参照した対象商品の正本を、新しい実行ID配下へ引き継ぐ処理です。旧DBを削除したり、新しい空DBから既存建玉を推測で取り込んだりしません。移行完了を確認してから通常起動します。元の設定と売買条件が異なるなど、移行が拒否された場合はDBを消して回避せず、表示された不一致を解消してください。退避する旧設定の相対保存先が変わらないよう、`conf-legacy` は元の設定フォルダと同じ親フォルダに置きます。

旧DBと旧ログは残します。移行元DBの隣には、`TOPIXmini.sqlite.migration.json` のような移行記録を作り、移行先・実行ID・元状態の指紋・完了状態を保存します。同じ旧台帳から別実行IDへの再複製は拒否します。途中シャットダウンで移行記録が残った場合も自動再移行せず、記録と移行先DBを確認します。移行記録を消してやり直す運用にはしないでください。

この版で移行した台帳は移行元データフォルダの場所も保存し、新版の運転中は旧版の起動と排他します。旧版が動いていれば、新版は注文台帳を変更する前に停止します。この更新以前に移行済みの台帳には移行元の場所がないため、その場合は旧exeを再起動しないでください。

すでに単一商品版の `conf-topix`・`conf-nk` を使っていた場合、旧フォルダは自動では読みません。実設定を対応する新商品フォルダの `conf` へ引き継ぎます。移動で相対保存先も変わるため、実行IDと既存DBを維持して保存先を旧正本へ向けるか、停止中に正本を移してから起動してください。旧状態を残したまま新しい空DBで再開しないでください。

## 時間と待機表示

途中起動・再起動時は二市場の当場生板をcontrollerから取得し、指標だけを準備します。過去売買の再実行、旧仮想候補・旧残玉の復元は行いません。準備後に受信した新鮮な板から今回の判断を始めます。日中・夜間の選定手法と米英夏時間の扱いは[運転と保存](運転と保存.md#時間による切替)を参照してください。

寄前の「採用0行」は、前場価格を当場指標へ混ぜなかったことを示します。旧T06とTG04/PG04の基本担当は60本EMA・3本分の傾き・公開待機が必要で、08:45開始なら方向判定は最短でも概ね09:50です。他担当はそれぞれの価格帯・入口条件で準備し、基本担当の準備完了を待ちません。

無約定でも既定30秒ごとに受信・判断時刻、今回の保有枚数、指標準備や通信の待機理由を表示します。同じ稼働記録のJSONには発注商品の気配による含み損益を追加し、D07/S01・TG04/PG04等では担当別の出口水準・追尾幅・残玉予算も残します。これらは診断情報で、売買条件を変更しません。詳細は[運転と保存](運転と保存.md)、注文照合は[APIと注文照合](APIと注文照合.md)、判断関数は[アルゴリズム](アルゴリズム.md)に記載しています。

## ビルド

このアプリフォルダで `go run ./cmd/build-dist` を実行します。Windows/Linuxとも `CGO_ENABLED=0` で、MinGWを必要としません。通常の再ビルドは実設定・既存ルール・SQLite・ログを保持し、不足する実ルールだけ追加します。
