# 日経の標準3手法

日経ラージ・mini・microは、次の時間割を使います。TOPIXの日中T06・夜間T04は従来どおりです。

| 時間帯 | 手法ID | 主な変更 |
| --- | --- | --- |
| 日中 | `NK225_D164_15` | J02の支持別数量を基に、初回失速待機・残玉保護・追撃の短期確認・追撃玉の50円逆行返済 |
| 夜間開始〜米国開始15分前 | `NK225_P164_06` | P05を基に、少量初回と利益返済後の残玉を保護し、追撃玉の50円逆行を返済 |
| 米国開始前後15分 | 静観 | 所有玉の返済と注文照合 |
| 米国開始15分後〜夜間終了 | `NK225_U165_03` | D07を基に、反対板の価格帯・表示数量が確認された初回を最大30秒待機 |

3つは別の手法IDです。旧S01・P05・D07の定義とルールは残り、商品をOFFにして照合を終えてから選び直せます。条件を変えたものを旧IDへ上書きする構成ではありません。

標準設定では立会終了10分前から返済します。通常の時刻ではデイ15:35、ナイト05:50です。米国開始前の返済とは別の、セッションを跨がないための終了処理です。

## 数量と判断価格

方向・支持・保護・返済判断には日経ラージの観測を使い、元手法が必要とする国内二市場の指標も維持します。米国の外部データは使いません。発注商品の気配と実約定は、発注価格・建玉ID・実損益の管理に使います。

元手法の通知と数量判断はmini10枚相当の共通尺度で扱い、実商品の片方向上限へ比例換算して整数に切り捨てます。1枚未満を切り上げて注文しません。数量が小さいと担当が0枚になり、研究の損益を単純倍率にはできません。完全返済ではその所有IDの残量を全て返済します。

日中の待機解除量は、最初に希望した数量と現在の支持による希望量の小さい方を使い、元の親に生きている数量でも制限します。待機中に支持が上がっても当初希望を超えて増量しません。未校正の支持スコアは勝率を意味しません。

## 利益保護と初回待機

日中の残玉保護は、元手法の部分返済が実際に利益を確定し、元の親にも残量があるとき、その時点の実所有残玉へ資格を付けます。対象玉が実建値から10円順行すると、建値を返済判断の床にします。追撃確認は5秒・15秒の順行、追撃玉の損切りは実建値から50円逆行です。

米国前は、元初回が100基準で20以下の少量初回に限り、10円順行で保護を起動し、最高順行幅から20円戻り・最低建値で返済を判断します。それ以外の利益返済後の対象残玉は、資格を得た後に10円順行すると建値の床だけを設定します。追撃玉には50円逆行の返済を加えます。

研究は次の正常板で一括約定する模型です。実運転の部分約定では、日中は対象返済注文、米国前は元の部分返済通知に対応する返済群が全量約定してから粗益を合計し、残玉の資格を判定します。プラスの約定片だけで先に資格を付けません。返済の未約定分は取消後も必要量を保持して再照合します。

米国後は反対方向の価格帯と数量支持がある初回を待機し、待機後の原行で自方向の新しい価格帯が確認された場合にだけ再開します。30秒を超えると当該親を取消し、その親の後続追加だけで再開しません。観測が未知なら、未知を反対圧力とみなして初回を止めません。表示数量の減少を約定・取消のどちらかと断定しません。

新規の撤回は指定された注文IDだけに適用します。未送信なら待ち列から外し、送信済みなら個別取消を一度だけ要求して、約定・取消の照合完了を待ちます。結果不明時に取消を再送せず、競合して成立した実玉は引き続き管理します。他担当の注文や返済注文をまとめて取消しません。

これらの床は返済を判断する条件です。次の板の変化や実約定の滑りにより、利益が出た玉でも最終返済が損失になる場合があります。

## 設定更新

`settings_version = 2`はアプリが管理する移行版です。旧標準のS01・P05・静観・D07という4枠と、旧3手法・移行先3手法の標準式が一致する日経商品だけを自動移行します。枠IDと順序、数量、OFF／DryRun／ON、接続先は保持します。独自境界・改変ルールは自動置換しません。版1で明示選択した日中D07も保持します。

読込だけでは実設定を書き換えません。通常の画面保存で移行版を記録し、その後旧手法を選び直した場合は再移行しません。更新時には実行ファイルと新しい3つの実ルールTOMLを配置します。既存の実設定・ルール・台帳を上書きしないでください。

各新ルールファイルには依存する旧手法の共通式も含めています。例えば`NK225_D07.toml`だけを変更しても、新しい3手法へ自動反映しません。専用式は[ルールエンジン](ルールエンジン.md)、時間の制約は[時間帯切替](時間帯切替.md)を参照してください。
