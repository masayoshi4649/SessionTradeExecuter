# TG04・PG04のルール

TG04とPG04も、入口・継続・出口の主な判断を外部TOMLのExpr式で設定します。標準値は従来のTG04・PG04と同じです。両者は別のルールファイル・別の評価器を読み込み、一方の変更が他方へ伝わりません。

| 範囲 | 識別子 | 既定の動き |
| --- | --- | --- |
| 通常入口 | `research.entry.*` | 40分帯の突破後の押し戻り、又は帯端の反発を準備し、方向支持を確認 |
| 追加担当と夜の独立入口 | `research.active.*` | 1.25R順行から0.75R追尾。追加担当は二市場逆行による全返済・半減も使用 |
| 日中の別入口 | `research.episode.*` | 20分帯を抜けてから内側へ回復したことを確認。帯中心で半数利確し、残りを固定帯幅で追尾 |
| 基本担当の採否・反証 | `research.core.*` | 120秒の逆流で新規を見送り、初回固定平均と方向の破綻が15秒続いたら返済 |
| 利益玉1枚の延長 | `research.residual.*` | 他の玉の実現利益で損失を限定し、残り1枚を3Rで追尾 |

TG04は基本・追加・別入口を5:3:2、PG04は基本・別入口を5:5で配分します。最大枚数、端数配分、所有建玉ID、注文確認、情報の公開時計、場末の強制返済は実行側で管理します。

基本担当の元の候補を作るT06・U06等は、その手法専用のルールを使います。TG04・PG04のルールを内部のT06等へそのまま渡しません。D07の51式と利益回転は別設定であり、今回のTG04・PG04用条件はD07へ適用しません。

入力は現在までに確認できた有限の数値と真偽値だけです。方向を掛けた入力は、候補方向への進行をプラスで表します。数値式の方向は`-1・0・1`、入口型は`-1・1・4`だけを認め、小数を整数へ丸めて注文しません。式を変更した場合の成績は、標準値の検証結果とは別に検証します。

式の定義・入力型・日本語説明の正本は `internal/rules/research_specs.go` です。編集は実際に読み込むルールTOMLに行い、再起動時に型検査して適用します。
