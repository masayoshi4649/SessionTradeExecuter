# D07の基本枠・残玉管理の外部条件

基本枠の入口確認、部分利確後の利益保護（P01）、残り1枚の追尾（R05）の判断式を外部TOMLに分離した。標準式では従来のD07と同じ条件を使う。TG04・PG04には適用しない。

| 条件ID | 標準の意味 |
| --- | --- |
| `core.fixed_r` | 初回Rは直前までのATRとラージ呼値8個分の大きい方。ATR欠測では呼値8個分 |
| `core.day_gate` | 昼は新規方向への120秒変化が−0.25R以上なら採用。未知ならこの確認を免除 |
| `core.peer_fresh` | 他市場の情報は15秒以内 |
| `core.night_gate` | 夜は両市場の120秒変化がともに新規方向へ逆行したときだけ見送り |
| `core.day_adverse` | 昼の120秒・20分変化が逆行し、現在MAが入口固定MAより0.1R以上逆行 |
| `core.adverse_hold_seconds` | 上記の反証が15秒持続したら返済 |
| `partial.start` | 昼基本枠の理由7・30・1435の実部分返済が黒字なら利益保護開始 |
| `partial.floor` | 開始後の残玉最高利益幅の50%を下限とする |
| `partial.exit` | 最高利益幅が正で、現在利益幅が下限以下なら残玉を返済 |
| `residual.eligible_reason` | 理由2・70・1437の全返済時に残玉化を検討 |
| `residual.profitable_lot` | 最古の利益玉1枚を候補とする |
| `residual.profitable_budget` | 残玉以外の返済見込益、および実約定後の利益が正なら残玉化 |
| `residual.budget` | 実現利益の正の部分を残玉の損失予算とする |
| `residual.width` | 通常3R。夜基本枠だけ16ラージ呼値（日経160pt）を上限とする |
| `residual.exit` | 利益予算下限と追尾下限の高い方を割ったら返済 |
| `residual.quiet_before_seconds` / `residual.quiet_after_seconds` | 残玉は米国寄付前後900秒を持たない |

式には確定した現在までの数値と既知フラグだけを渡す。例えば `partial.floor = 0.75 * best` なら、部分利確後に残玉で得た最高利益幅の75%まで戻った地点で保護する。実際のTOMLではキーと式を引用符で囲む。

```toml
"partial.floor" = "0.75 * best"
```

TOMLは全条件が必要。起動時に型・キー・式を検査し、実行中の評価失敗は注文を送る前に停止する。変更は再起動後から適用する。式を変更した結果の成績は、標準D07の検証結果とは区別する。

注文IDと建玉ID、未約定照合、数量上限、現在板の有効性、将来時刻の拒否、場末の全返済はGo側に残す。Rは外部式でも最小呼値を下回らない。反証判定は無効板と15秒超の受信断で連続時間をリセットする。

P01は実部分約定時の残玉平均建値を固定し、その時刻以前の最高値を引き継がない。部分返済が照合中でも最高利益と返済条件の監視を続け、照合完了後に必要な残玉だけを返済する。元の強制返済や場末返済を式で取り消すことはできない。

D07の判断用利益予算は費用0円の研究条件を維持する。約定ログには実際の費用と費用後収支を別途記録する。出口画面の利益下限・残玉追尾幅も、実際の返済判定と同じ外部式から計算する。
