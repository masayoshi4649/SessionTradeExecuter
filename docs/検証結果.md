# 検証方法と確認範囲

このリポジトリのソース・ルール・fixtureを使って、配布・設定・状態遷移・注文照合・保存の整合性を確認します。外部の研究資料や作業フォルダをビルド・単体試験の前提にしません。過去の照合件数や損益を、この独立版の実施結果として引き継ぎません。

## ソースと配布

リポジトリのルートで次を実行します。

```text
go test ./...
go vet ./...
go run ./cmd/build-dist
```

- Windows/Linux amd64を `CGO_ENABLED=0` でビルドすること。
- 出力が `dist/{windows|linux}-amd64/SessionTradeExecuter/session-trade-executer[.exe]` となること。
- 初回設定が全商品OFFで、全12手法の実ルールが配置されること。
- 再配布で既存の実設定・画面保存設定・改変ルール・台帳・ログを変更しないこと。不足するルールだけ追加すること。
- 片方のOSのビルドが失敗した場合、既存配布物を更新しないこと。旧配置や未知ファイルを削除しないこと。
- 任意の作業フォルダから実行しても、実行ファイル隣の `conf` を読み、CLI引数を受け付けないこと。

配布済みバイナリの疎通は、新規設定又は全商品OFFの設定で実施します。既存設定には保存済みliveが含まれる場合があるため、初回配布のOFFとは区別します。

## ルールと時間

条件式の型・未知名・銘柄と昼夜の対応、時間枠の重複・境界、米英夏時間を確認します。日経標準3手法と従来手法のID・式・数量を変更しません。未確定足・未公開情報・未来の価格を判断へ混ぜず、当場履歴は指標の準備だけに使います。

保存復元、上下対称、部分約定、親利益保護、利益床、時間枠切替後の初期化を、各手法のテストとfixtureで確認します。fixtureの説明は [内部照合データ](../internal/strategy/testdata/README.md)、条件式は [ルールエンジン](ルールエンジン.md)を参照してください。

## 注文と所有

模擬API又はDryRunで、送信前保存、送信結果不明、受付と実約定の分離、部分約定、FAK終了、取消競合、再送防止を確認します。返済対象が当起動の所有建玉IDに限定されること、再起動で旧実玉を手動管理へ移すこと、OFFで架空返済を追加しないことを検査します。

SQLite・ロック・再起動の検査では、既存のDB形式・所有情報・排他名を維持します。状態や台帳を消して起動を成功させる回避は行いません。詳しい注文仕様は [APIと注文照合](APIと注文照合.md)を参照してください。

## 画面と記録

設定版の競合、保存失敗、OFF照合中の待機、稼働中の設定拒否、保存済みモードの再起動反映を確認します。終了CSVの6列・集計CSVの7列、削除済み履歴を再生成しないこと、管理外移管とViewer用JSONLを検査します。

[SessionTradeViewer](https://github.com/masayoshi4649/SessionTradeViewer)との連携は、その独立した [データ仕様](https://github.com/masayoshi4649/SessionTradeViewer/blob/main/docs/データ仕様.md) と [画像API](https://github.com/masayoshi4649/SessionTradeViewer/blob/main/docs/画像API.md)を読取契約とします。Executerの所有会計とViewerの原板気配による参考評価は区別します。

## 結果の読み方

単体試験・fixtureの一致は実装整合性の確認であり、実口座の約定価格や将来の収益性を保証しません。DryRunの新鮮な発注商品気配、実取引の確認済み約定、全量一括の仮想約定は同じ模型ではありません。途中起動・通信断・部分約定・取消照合により経路が変わります。

実施結果を記録する場合は、対象バージョン、環境、実行コマンド、対象範囲、未確認事項を併記し、実行していない確認を合格扱いにしません。
