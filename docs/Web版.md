# Web版の設定と操作

Windowsは`dist/windows-amd64/SessionTradeExecuter/session-trade-executer.exe`、Linuxは`dist/linux-amd64/SessionTradeExecuter/session-trade-executer`を引数なしで起動します。同じPCは`http://localhost:8090/`、別PCは`http://起動PCのIPアドレス又はホスト名:8090/`を開きます。全インターフェースで待ち受けます。Windowsでは受信TCPポートの許可も必要です。

## 画面から操作する

商品カードの **OFF / DryRun / ON** で、一商品ずつモードを選びます。日経miniを実取引、日経microを仮想売買とする使い方ができます。ONは実トレードです。新規配布は全商品OFFです。

| 操作 | 動作 |
|---|---|
| OFF | 自分の未約定注文・予約を取消し、照合後に運転を止めます。既存建玉は決済せず管理対象から外します。 |
| DryRun | 実注文を送らず仮想売買します。 |
| ON | 当商品の実注文を送ります。 |
| ⚙ オプション | OFFで取消・照合が完了した商品について、Qtyと時間帯ごとの手法を変更します。稼働中の変更はAPIでも拒否します。 |
| 全般設定 | controller接続先、米国時間などの共通時刻、通信・保存先・待受設定を変更します。共通運転設定は対象商品をOFFにしてから保存します。 |

Qtyは**買い・売りそれぞれの最大保有枚数**です。注文一回の枚数ではありません。各手法が上限内で担当へ配分します。mini/microの判断板は従来どおりラージを使います。

日経3商品の標準は日中`NK225_D164_15`、米国開始15分前まで`NK225_P164_06`、前後15分の静観、開始15分後から`NK225_U165_03`です。TOPIXは日中T06・夜間T04を維持します。 詳細は[新標準手法](新標準手法.md)を参照してください。旧S01・P05・D07も選択できます。

売買管理カードの確定損益・手数料・直近約定は当セッション分です。場替わりで前場分を引き継ぎません。同じ場での再起動は確定約定を再集計しますが、旧建玉は管理対象に戻しません。

**「セッション損益」タブ**では、終了確定後の `log/sessionPL.csv` を読み、商品と実売買／DryRunで絞り込めます。金額は手数料前の利益・損失・収支です。表示中は5秒ごと、又は更新ボタンで再取得します。削除したCSVや行は表示せず、DBから復元しません。読取失敗時は前回値と取得時刻を残し、失敗を明示します。[CSVの列と終了条件](セッション損益.md)を参照してください。

手法候補は`conf/rules`の実TOMLから、`NK225_`・`TOPIX_`の接頭辞を読み取って取得します。日経のラージ・mini・microは`NK225_`を共通使用します。昼夜への対応と本文の型を検査し、未実装の名前や不正な本文は選べません。ファイルの複製・改名だけで新たな戦略の状態遷移を作る機能ではありません。

## OFFと再開時の所有範囲

**OFFにした建玉は、含み益・含み損があっても自動返済しません。以後は手動管理です。**

OFF確定後は新規・返済の送信を禁止し、台帳に所有を記録した未約定注文・予約だけを取消します。送信中に既に受付・約定された注文をなかったことにはせず、確認できた約定を保存します。取消結果が不明な間は「切替待ち」、照合できない場合はエラーを表示し、次の運転を勝手に開始しません。手動注文・他商品の注文を一括取消しません。

再びDryRun／ONにした場合は新規運転です。旧玉・旧利益予算を引き継がず、当場履歴は指標準備だけに使用します。旧実建玉が残っていても、その枚数を新しい運転のQtyへ混ぜません。DryRunとONの直接切替も、旧運転の注文整理・管理終了後に新しい運転を開始します。

ブラウザを閉じても運転は続きます。アプリそのものを`Ctrl+C`で終了する場合は従来の終了処理として稼働中の所有玉の返済を試みます。建玉を決済せず管理終了したい場合は、画面でOFFにして注文照合完了を確認します。

## 保存と反映

画面で保存した内容は、実行ファイル隣の**`conf/web-ui.toml`**に日本語コメント付きで保存します。元の`settings.toml`や複数の設定ファイル・非公開の設定値は保持し、次回起動も`web-ui.toml`の公開項目を優先します。TOMLを手作業で編集する必要はありません。

- モード、Qty、時間帯ごとの手法、共通運転設定は画面操作で保存・適用します。OFFの注文照合中は切替完了を待ちます。
- 保存したON/DryRunは次回起動にも適用します。停止状態で再起動したい商品は先にOFFを保存します。
- 待受IP・ポートの変更は保存後のアプリ再起動で反映します。画面に「再起動が必要」と表示します。
- 米国・英国の基準は**冬の日本時間**です。各市場の夏時間には自動で1時間早めます。
- 外部ルール本文の一括再読込はアプリ再起動時です。手法選択時は選択先の実ファイルを検査します。
- 複数の画面で同時に編集した場合は版番号を照合し、古い値による上書きを拒否します。ディスクへの書込失敗も保存成功として扱いません。

旧`enabled`と全体`trading.dryrun`の設定も読めますが、新画面では商品別`mode="off" / "dryrun" / "live"`を使用します。

旧標準のS01・P05・静観・D07の4枠と新旧の標準式が一致する日経商品だけを新3手法へ移行します。独自時間枠・数量・モード・接続先・改変式は保持します。移行版`settings_version=2`は通常保存で記録し、その後の明示的な旧手法選択を再移行しません。読込だけで元ファイルは書き換えません。

## 画面とREST API

静的HTML/CSS/JavaScriptが表示を担当し、GoのREST APIが検証・保存・運転を担当します。画面には取引ロジックを置きません。配布時は両者を一つの実行ファイルに収録するため、Node.jsの導入は不要です。

| メソッド・パス | 用途 |
|---|---|
| `GET /api/state` | 商品別の希望モード・実運転モード・切替待ち・保有・損益・操作トークン |
| `GET /api/settings` | 編集用の全公開設定と保存版`revision`。保存失敗時の緊急OFFは画面状態を優先して返します。 |
| `GET /api/rules` | 実ファイルの候補、銘柄、昼夜対応、時間枠専用かどうかと制約、選択不可の理由 |
| `GET /api/session-pl` | 現存する終了集計CSVを読み、`rows`へ`session / product / mode / profit / loss / net / entry_qty`を返す。ファイルなしは空配列、読取・解析失敗は500。 |
| `PUT /api/products/{product}/mode` | `{mode, revision}`で個別モード保存 |
| `PUT /api/products/{product}/settings` | `{max_per_side, day, night, windows, revision}`で商品オプション保存。既存の時間帯枠は省略できません。 |
| `PUT /api/settings` | `GET /api/settings`と同じ構造で共通設定を保存 |

PUTは`Content-Type: application/json`と`X-CSRF-Token`が必要です。成功時は`settings`・`state`・`message`・`restart_required`を返します。不正形式は400、不明商品は404、稼働状態や保存版の競合は409です。モード変更は専用APIを使用し、全般設定PUTからの変更は拒否します。GET以外は同一オリジンの操作を検査します。接続元IPやホスト名の限定はありません。

OFFは設定保存に失敗しても管理終了を優先し、エラー表示を残します。この場合はディスク上の起動モードが以前のままなので、保存先を復旧してOFFを選び直すか、他の設定保存で現在のOFF状態を永続化してください。

## 記録と配布

商品ごとの注文・約定・建玉IDを独立したSQLiteで管理し、仮想／実取引も分離します。OFF前の約定・所有状態は監査記録として残します。

```text
data/{dryrun又はlive}/{商品名小文字}/
log/{Product}/{Session}.csv
log/{Product}/{Session}_dryrun.csv
log/sessionPL.csv
log/web/操作.jsonl
conf/web-ui.toml
```

`操作.jsonl`には設定変更と商品別運転の小さい記録を残します。終了確定後の商品別6列CSV・全商品7列の`sessionPL.csv`に加え、[Viewer連携](Viewer連携.md)の小さい約定JSONL・一覧を出力します。旧モード別の詳細CSV・旧約定JSONL・`session_summary*.csv`・`trace.jsonl`は追加も再作成もしません。既存の旧ファイルは自動削除せず、SQLiteの注文・約定・判断根拠は保持します。詳細の転送には明示操作で[診断ZIP](診断データの出力.md)を作ります。同一controller・商品・モードの二重起動ロックを維持します。レポート保存エラーは全ページの警告へ表示します。

`go run ./cmd/build-dist`でWindows/LinuxをCGOなしで生成します。既存の実設定・画面保存設定・ルール・台帳・ログは通常の再配布で上書きしません。
