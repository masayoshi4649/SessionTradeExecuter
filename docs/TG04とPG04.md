# TG04・PG04の設定と動作

現在の日経標準は[新標準3手法](新標準手法.md)です。TG04・PG04も日経ラージ・mini・microの従来手法として選択できます。全5商品を一つの実行ファイルで扱い、商品をOFFにして注文照合を終えてから手法を変更します。

商品設定の抜粋です。画面からの選択に加え、時間帯枠の `method` へ銘柄付きIDを指定できます。

```toml
[[instruments]]
product = "NK225mini"
mode = "off"
max_per_side = 10
day = "NK225_TG04"
night = "NK225_TG04"
```

PG04は `NK225_PG04` を選びます。ルール本文は `conf/rules/NK225_TG04.toml` 又は `NK225_PG04.toml` です。旧 `[algorithm]` の係数上書きとの併用は拒否します。数量配分・入口・継続・出口の定義は以下のとおりです。

## 2手法の違い

|手法|基本担当|既存追加担当|別の入口を使う担当|
|---|---:|---:|---:|
|TG04・上限10枚|5枚|3枚|2枚|
|PG04・上限10枚|5枚|なし|5枚|

基本担当は、昼は方向追従に自己120秒逆流の入口除外と固定入口MA20の破綻確認、夜は突破・押し戻りと二市場逆流の入口除外を使います。TG04の追加担当は40分の価格帯の状態を見て追従・反発を切り替えます。別入口は、昼は20分帯を外へ抜けた後の回復、夜は40分の往復帯の端からの反発です。

各担当は独立して動き、余った枚数枠を貸しません。判断の元となる仮想候補と、実約定した建玉を分けて管理します。元候補を見送っても、その波の終了までは候補生成の状態を進めます。

基本担当と別入口担当は、元の利益追尾が全返済を通知したとき、**最古の利益玉1枚**を残す資格を検査します。他玉の返済後に、新規・返済手数料を引いた実現利益が正なら、その100%を損失予算とし、初回判断で固定したRの3倍の追尾と併用します。Rは公開ATRと日経ラージ8呼値の大きい方です。含み益は予算に含めません。損切り・米国静観・場末返済では残しません。

残玉がある担当の後続の親取引は、その初回通知時に見送ります。別担当は継続します。最古玉を残すため、返済する建玉IDと枚数を明示して発注し、部分約定後も返済目標を維持します。

## 枚数と価格

上限は任意の正整数です。TG04は5:3:2、PG04は5:5で整数配分し、端数は小数部分の大きい担当から、同率は基本・追加・別入口の順に配ります。TG04の11枚は6/3/2、2枚は1/1/0です。0枚の担当は停止します。

上限に数えるのは今回の起動で所有する玉と新規予約です。前回の実建玉と手動建玉は含めず、例えば旧1枚を残して上限10枚で起動すれば、今回の10枚と合わせて口座11枚になり得ます。返済対象も今回の所有IDだけに限定します。

上限を増やしても、別入口の初回2枚や追撃1枚、残玉1枚まで全てを比例拡大する仕様ではありません。小さい枠では初回も縮小します。**研究成績は日経mini・上限10枚の結果**であり、他商品・他枚数への倍率換算ではありません。

判断には日経・TOPIXのラージを使います。実発注とdryrun約定は、選んだ商品自身の気配を使います。研究はラージ気配をmini約定へ代用しているため、商品間の価格差や送信・約定遅延によって結果は異なります。

## 時刻・履歴・再起動

場内返済はcontrollerの終了時刻と `schedule` の終了前秒数から決めます。標準はデイ15:35・ナイト05:50です。米国開始は日本時間の設定から夏時間を反映します。03:00は研究の保有率集計の区切りであり、売買停止時刻ではありません。

途中起動・再起動とも当場の二市場原板を取得し、特徴量だけを準備します。過去の仮想売買を再生せず、旧候補、固定MA/R、確定利益、残玉予算も引き継ぎません。準備完了後の新鮮な板で新しい候補と取引を作ります。寄り付きから継続運転した研究結果と、途中起動した運転結果が同じになる保証はありません。

毎回の起動で新しい注文名前空間を作り、空の状態から始めます。実注文では旧台帳の所有未確定注文・条件予約だけを取り消し、途中約定も含めて終了を照合します。未確定のままなら起動を止めます。旧実建玉は自動返済せず手動管理へ移します。仮想運転の旧玉・送信待ちは引き継がず、過去の清算約定を追加しません。

手法ID・枚数・時刻を変更して再起動できます。旧状態の監査保存と新状態への切替は原子的に行い、全約定履歴と旧DBを維持します。商品と実注文・仮想の区別は保存先と一致する必要があります。運転中のconf変更は反映しません。通信だけが一時切断した場合は、新しい起動とは異なり、今回の所有状態を維持して再同期します。

## 費用と記録

標準片道手数料は日経275円、mini38.5円、micro11円です。1注文の累積約定枚数に対して1円未満を切り捨て、分割約定ではその差分だけ計上します。証券会社が確定した請求額ではなく標準費用の見積りです。

元研究の候補通知を生成する内部の仮想計算は、研究どおりminiの倍率100円・片道38.5円で進めます。実建玉の会計と残玉予算は、選択した商品の倍率・手数料・確認済み約定を使用します。

SQLiteの約定記録には、費用前実現損益に加え、標準手数料、新規建玉ID、返済建玉内訳、内訳の根拠を保存します。詳細CSV・JSONLは明示操作の診断ZIP内にだけ出力します。費用後合計は全行の実現損益合計から新規・返済両方の標準手数料を引きます。旧記録に存在しない費用を後から捏造しません。

実返済の個々の明細と元建玉の対応が上流から直接渡されない場合、口座残数の減少を照合し、指定内訳に配賦したことを記録します。残す1枚は返済対象から除外します。判断根拠には手法・担当・親ID・固定水準・実現利益・残玉予算を残します。

既定30秒ごとの稼働JSONに、担当ごとの実枚数、内部仮想候補の出口、追尾開始幅・追尾幅、利益予算を追加しました。発注商品の気配による費用前含み損益と、判断に使うラージ板での参考損益は区別します。気配が古い場合は評価を省略します。出口診断は観測情報であり、利確条件自体は変更していません。

原板・最新状態はSQLiteに保持し、traceでは全状態の反復コピーを省きます。重いDBの転送には、[対象場の診断ZIP](診断データの出力.md)を利用できます。APIに接続せず、対象場の全約定と要約を1ファイル8MiB以下へ分割して出力します。

実装は `internal/strategy`、条件式は `conf/rules` へ分離しています。確認手順は[検証方法](検証結果.md)を参照してください。
