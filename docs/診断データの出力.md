# 転送用の診断ZIP

必要なときだけ、対象セッションの診断ZIPを作れます。通常運転では`trace.jsonl`や旧詳細CSV・約定JSONLを生成せず、注文・約定・判断根拠をSQLiteへ保存します。診断出力はその既存SQLiteを読み、注文・取消・返済・controllerへの接続を行いません。旧ログが削除されていても、その再生成を必要としません。

実行ファイル隣の `conf/settings.toml` の既存 `[startup]` を次のように変更します。同じテーブルを追加して二重定義しないでください。

```toml
[startup]
# diagnosticsは保存済み資料の書出しだけを行います。
action = "diagnostics"
# 調べるセッション。空文字または省略なら最新の記録場です。
diagnostic_session = "2026-10-26_Day"
```

実行ファイルを引数なしで起動すると、設定したログ保存先の `diagnostics/` にZIPを作り、画面にも保存先を表示します。Web版は商品設定の `mode="live"` なら実注文のDB、それ以外は仮想売買のDBを読みます。対象の記録に合わせ、商品と保存先を元の運転に合わせてください。`action="diagnostics"` 中は運転モードにかかわらず注文APIへ接続しません。

診断後に通常運転へ戻すときは `action="run"` に戻し、`diagnostic_session` を削除または空文字へ戻します。既に動いているプロセスの設定を変更したり、停止・返済させたりする操作ではありません。運転中のDBも読み取れますが、商品DBと市場DBの保存時点は完全同時ではありません。

## 転送するファイル

`2026-10-26_Day_NK225mini_live_生成日時_part001.zip` のような名前です。1ファイル8MiB以内へ自動分割し、複数あれば同じ生成日時の `part` 全てを使用します。それぞれ独立したZIPなので、別のpartがなくても解凍できます。

含む情報は次のとおりです。

- 対象場の全約定CSV・JSONL。診断操作時だけZIP内へ生成し、枚数、価格、担当、理由、標準手数料、建玉ID、判断根拠を保持します。通常の6列終了CSVとは別の詳細資料です。
- 対象場の判断・稼働・異常イベント。全状態の反復コピーと入力保存通知は省略し、省略の範囲を記録します。
- 出力時点の実保有・未確定注文・保存版と、TG04/PG04の残玉予算・仮想候補の出口水準の要約。過去場を指定しても、この要約は現在状態です。
- S01では `current_s01_state.jsonl` に初回確定枚数、親の最高利益・保護床、再参加拒否、基準D07の仮想保有・予約件数を要約します。基準の仮想玉は実保有に含めず、影の全注文履歴を転送しません。
- 商品、枚数、手法ID、時刻設定、実行ファイルの版情報。これは**診断書出し時の設定**であり、対象セッションの運転当時の設定と同一とは限りません。接続先URLや設定ファイル全体は含めません。
- `manifest.json` と `summary.json`。対象範囲、元連番、件数、省略、各断片の指紋を記載します。

原板全量、全復元snapshot、過去全セッションのtraceは含めません。256KiBを超える単一イベント本文も省略を明示して要約しますが、約定そのものの原JSONL・CSVは省略しません。何を見て利確を待ったかの情報が旧版に記録されていない場合、この出力で過去の根拠を作り直すことはできません。

旧台帳更新と最新snapshotが16MiBを超える場合、巨大JSONの構文解析を避け、バイト数・元連番または改訂番号・時刻・省略理由を出します。この場合の実保有・未確定注文・出口水準は「不明」であり、0枚や注文なしとは扱いません。対象場の全約定は引き続き収録します。巨大イベント本文をSQLで省略する際は元本文のSHA256を新たに算出せず、元DB名・連番・種類・相関IDで対応付けます。ZIPに格納した各断片のSHA256とは区別します。

CSV/JSONL/JSONは容量を制限するため連番の断片としてZIPへ格納します。閲覧用に戻す場合は、manifestの `logical_file` ごとに `fragment_index` 昇順でバイト連結します。断片境界が行や日本語文字の途中に来る場合があるため、文字列として加工せず連結してください。通常は生成したZIPをそのまま診断に使用できます。

## 保存元への影響

読取は `mode=ro`・`query_only` とし、WALに保存済みの確定内容も読みます。元の約定・建玉・原板・events・snapshot・既存ログは変更しません。存在しないDBを新規作成することもありません。診断出力は別フォルダです。

1ZIPだけでも失敗した場合、処理はエラーを返します。既に確定したpartは残る場合がありますが、最後のmanifestが `final_part=true` になる一式を使用してください。
