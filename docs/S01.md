# S01の日中運転仕様

現在の標準は[新標準3手法](新標準手法.md)です。このページは引き続き選択できる旧手法の定義を説明します。
`NK225_S01`は、日経ラージ・mini・microの日中用手法です。D07を基に、別入口担当の利益回収と、利確後の新しい親取引への再参加だけを変更します。夜間・TOPIXには選択できません。

## 変更する部分

片方向上限10枚では、元D07の主担当5枚・追加担当3枚・別入口担当2枚の独立配分を維持します。主担当と追加担当の入口・出口は元D07のままです。S01は初回5枚を小分けにする手法ではありません。

別入口担当は、同じ親取引の「手数料前の確定損益＋残玉を返済側のラージ気配で評価した含み損益」を追跡します。

1. 初回の実約定数量を`q0`、入口で固定したリスク幅を`R`とします。
2. 親全体の利益が`0.5 × R × q0 × 商品の1pt当たり金額`に届いたら利益保護を開始します。
3. 保護開始後の親最高利益の50%を返済判断の床とし、床以下になったら当親の残玉を全返済します。追加・部分利確・残り1枚への移行で床を初期化しません。
4. 元の損切り・部分返済・場末などの退出条件は優先し、返済が必要な行で追加新規を出しません。

同時に、**元D07を独立した仮想口座で動かします**。この仮想口座の別入口担当が旧親を保有又は注文予約している間は、S01の早期利確で空いた枠から異なる新親を採用しません。一度拒否した親は後追いせず、次の新親で再判定します。基準側の将来の返済時刻は参照しません。

仮想基準は同じ枚数上限の日経mini・手数料0・次の正常なラージ気配による約定で進みます。仮想の新規や返済を証券会社へ送信せず、実保有の表示・枚数上限・約定CSVへ混ぜません。実商品側の約定価格や遅延が変わっても、基準側の売買系列は独立して継続します。

## 実約定と通信

初回注文が分割約定した場合、全約定又は取消照合が完了するまで`q0`を確定しません。未約定分を保有として数えず、確定した累計実約定数量で保護の起動を判断します。確定前のピークを後から遡って保護起動へ使いません。追加注文の枚数は`q0`へ加算しません。

履歴の再取得や古い受信では、利益の水準と仮想基準だけを進め、S01利益床による新しい返済判断を作りません。復帰後の新鮮な観測でまだ床を割っていれば、その時点で返済を判断します。一方、過去の新鮮な観測ですでに成立した返済依頼は保持します。後から価格が回復したことを理由に、送信済み・結果不明の注文を取り消した扱いにはしません。

返済の床は発注判断の基準であり、同額での約定保証ではありません。実注文はcontrollerの生APIリダイレクトを使用し、当運転が所有する建玉IDだけを返済します。手数料はD07と同様、戦略の利益予算では除外し、実約定ログと画面の損益では記録・控除します。

## 設定と切替

旧標準の時間割は、日中S01・米国前P05・静観・米国後D07でした。現在の時間割と移行は[新標準手法](新標準手法.md)を参照してください。

商品の⚙で、OFF・注文照合完了後に手法と上限枚数を変更できます。S01の条件式は`conf/rules/NK225_S01.toml`の`s01.guard_active`・`s01.guard_floor`・`s01.entry_allowed`です。既存のExprルールエンジンで評価し、ファイルには各式の日本語コメントがあります。

版番号のない旧標準D07は旧S01移行を経由し、新旧の標準式と時間割が一致するときだけ現在の標準へ進みます。独自設定・改変式は保持します。S01を明示して保存した後はその選択を維持します。

毎起動・再ONは新規運転です。起動前の履歴は指標の準備だけに使い、元D07の仮想売買も新鮮な受信から始めます。時間枠・昼夜の切替では旧所有注文と玉の解消後に親利益床・仮想基準を初期化し、共通指標だけを必要に応じ継続します。手動OFF時に保有を管理外へ移す既存仕様は変更しません。

## 確認範囲

部分約定、古い受信、保存復元、親利益保護と再参加の拒否を、同梱のテストとfixtureで確認します。仮想の全量約定と実際の部分約定は異なるため、実約定価格や将来の収益は保証しません。確認手順は[検証方法](検証結果.md)を参照してください。
