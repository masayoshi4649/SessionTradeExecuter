# セッション損益と終了時のCSV

売買管理カードの確定損益・手数料・直近約定は当セッション分です。日中と夜間の切替では前場分を引き継ぎません。同じ場の再起動やOFFからの再開では保存済み確定約定を合算しますが、旧建玉・旧利益予算を新しい運転へ復活させません。

**「セッション損益」タブは、終了してCSVへ確定した場だけを表示します。** 当場の途中経過とは別です。表示元は `log/sessionPL.csv` で、SQLiteや旧集計CSVを使って欠けた履歴を補完しません。以下の `log` は設定のログ保存先です。

## 商品別の約定CSV

```text
log/NK225mini/2026-10-28_Day.csv
log/NK225mini/2026-10-28_Day_dryrun.csv
```

実売買と仮想売買を別ファイルへ保存します。1行は確認済みの1約定で、列は次の6つです。

| 列名 | 内容 |
| --- | --- |
| 売買種別 | `LongN`＝買い新規、`LongR`＝買い玉の売り返済、`ShortN`＝売り新規、`ShortR`＝売り玉の買い返済 |
| price | 約定価格 |
| qty | 約定枚数 |
| timestamp | `Trade.At`に記録された約定の時刻。タイムゾーン付き |
| 損益 | 符号付きの確定粗損益。新規は0、返済利益は正、返済損失は負 |
| 手法ID | その注文に保存された手法ID |

手法IDは終了時の設定から付け直しません。場内で手法を切り替えた場合も、各注文の手法を保持します。過去記録で特定できない手法は「不明」とし、現在の設定で埋めません。

## 全商品の集計CSV

`log/sessionPL.csv` は次の7列です。

| 列名 | 内容 |
| --- | --- |
| 利益 | 正の返済粗損益の合計 |
| 損失 | 負の返済粗損益の絶対額合計。正の金額で表示 |
| 収支 | 利益−損失 |
| 新規建合計qty | 新規建て合計枚数。注文数や最大保有枚数ではない |
| セッション | 対象の場 |
| 銘柄 | 商品名 |
| モード | `live`＝実売買、`dryrun`＝仮想売買 |

セッション・商品・モードの組につき1行です。同じ場で再起動しても別行を重複追加せず、同じ組の確定約定を合算します。同じ商品・場の実売買とDryRunは別行で、混ぜて集計しません。運転した無取引の場は0円、停止していて記録のない場は補いません。

このCSVの金額は**手数料前の粗損益**です。当場カードの手数料後収支とは定義が違います。手数料はSQLiteの約定記録へ残します。未返済の含み損益や、管理外へ移した玉の後日の手動決済は、この確定粗損益へ加えません。

## 終了・OFF・途中停止

CSVは立会終了時刻を迎え、未送信の新規・返済待ち列が空になり、未確定注文・未反映約定の照合が終わってから出力します。通常の返済開始時刻や、米国開始前後の手法切替だけではセッション終了とみなしません。

OFFは立会セッションの終了ではありません。注文の取消・照合後にその運転を終え、既存玉は返済せず管理外へ移します。同じ場で再開した場合は確定約定を合算します。管理外の玉がある場合も、CSVへ架空の返済を追加しません。

アプリが途中で止まった場合は、その時点だけで終了CSVを確定しません。再起動後、終了済みの場と注文状態を確認して出力します。注文の結果が分からない間は確定を待ちます。旧場へ帰属する遅延約定は元のセッションへ記録し、現存する終了CSV・集計行を訂正します。

新方式で報告対象に登録した場だけを出力します。更新前のDBにある全セッションを、起動時に新しいCSVへ一括変換することはありません。

## 削除した履歴と保存失敗

出力済みの印をDBへ記録するため、利用者が削除した商品別CSV・集計CSV・集計行を、起動や遅延約定を理由に復元しません。集計CSVやその行がなければ履歴画面にも表示しません。商品別の約定CSVだけを削除した場合は、現存する集計行の表示は残ります。集計ファイル全体を削除した後に別の場が終了した場合も、削除済みの過去行をまとめて戻す処理はしません。

書出し途中の失敗ではエラーを表示します。確認済み約定のDB保存を巻き戻したり、取引を再送したりしません。出力の再試行は同じセッション・商品・モードを更新し、重複行を作りません。

上記の6列CSVと7列の`sessionPL.csv`に加え、SessionTradeViewer用の小さい`*.trades.jsonl`と`sessionviewer.resources.json`を出力します。こちらは場中も確認済み約定・管理外移管が増えた時だけ更新します。[Viewer連携](Viewer連携.md)を参照してください。旧`log/{モード}/{実行ID}/{商品}/`の詳細CSV・旧約定JSONL・`session_summary*.csv`と、各`trace.jsonl`は、更新後に追加・再作成しません。既にある旧ファイルは自動削除しません。

SQLiteの約定・注文・所有ID・判断根拠は引き続き保存します。必要な詳細は明示操作で[診断ZIP](診断データの出力.md)へ書き出せます。Webの小さい操作記録`log/web/操作.jsonl`も継続します。終了CSVを削除することと、実建玉・注文・SQLiteの履歴を削除することは別です。
