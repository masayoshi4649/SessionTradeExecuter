# 条件式の編集

現在選択できる手法の条件を **Expr** で評価します。`conf/rules`のTOMLを編集して再起動すれば、Goを再ビルドせず条件を変更できます。運転中の自動再読込は行いません。`rules`内には実ルールだけを置き、sampleは生成しません。

| ファイル | 対象 | 設定する手法ID |
| --- | --- | --- |
| `NK225_D164_15.toml` | 日経・日中標準 | NK225_D164_15 |
| `NK225_P164_06.toml` | 日経・米国開始15分前まで | NK225_P164_06 |
| `NK225_U165_03.toml` | 日経・米国開始15分後から | NK225_U165_03 |
| `NK225_S01.toml` | 日経・日中 | NK225_S01 |
| `NK225_D07.toml` | 日経・昼夜 | NK225_D07 |
| `NK225_P05.toml` | 日経・米国開始15分前までの夜間枠 | NK225_P05 |
| `NK225_TG04.toml` | 日経・昼夜 | NK225_TG04 |
| `NK225_PG04.toml` | 日経・昼夜 | NK225_PG04 |
| `NK225_T06.toml` | 日経・日中 | NK225_T06 |
| `TOPIX_T06.toml` | TOPIX・日中 | TOPIX_T06 |
| `TOPIX_T04.toml` | TOPIX・夜間 | TOPIX_T04 |
| `NK225_U06.toml` | 日経・夜間 | NK225_U06 |

実ルールは計12ファイルです。mini・microも対応するラージ市場の手法ファイルを使用します。商品の時間帯枠の`method`へ銘柄付きの手法名を指定すると、その手法のルールへ切り替わります。枠未指定時の互換選択は`day`・`night`です。S01は日中、P05は米国開始前の夜間枠だけに対応します。別銘柄の手法名は設定エラーです。旧設定の短いIDは互換用に受け付けますが、新しい配布・画面・稼働ログは銘柄付き表記へ統一しました。

運転設定は`conf/settings.toml`です。

```toml
[rule_engine]
# 実行ファイル隣を基準にするルールフォルダ。
directory = "conf/rules"
```

式には数値、真偽値、比較、論理演算、三項式、`min`・`max`・`abs`を使えます。ファイル内の各コメントに用途と入力を記載しています。省略・未知名・型違いは起動時エラーになります。`startup.action="check"`で通信せず検査できます。

標準の式は各手法の従来条件と同じです。変更後の収益性を保証するものではありません。幅や待機時間を変更する場合は、まず仮想売買で確認してください。

新3手法はそれぞれS01・P05・D07の共通式と専用式を同じファイルに持ちます。依存元の旧ファイルを変更しても新手法へ自動反映しません。専用式は`d164_15.*`、`selected.p164_06.*`、`selected.u165_03.*`です。数量の整数配分・Source量の同期・板の価格帯状態はGoで管理します。[動作と移行](新標準手法.md)。

## 外へ出した部分

- S01の波担当の親利益保護開始、最高益に対する床、並行する元D07の別親占有中の入口抑制：[S01](S01.md)。
- P05の仮想B04入口の幅と効率、実玉の利益追尾開始・返済：[P05](P05.md)。
- 追加担当の通常入口、方向確認、部分利確、追尾幅、押し戻りからの取り直し、再参加・反転の条件。
- 基本担当のD07用入口判定、部分利確後の利益保護、夜間に残す1枚の条件と追尾幅。
- 詳細：[追加担当](ルールエンジン_addon.md)・[基本担当](ルールエンジン_core.md)。
- TG04・PG04の通常入口、追加、別入口、入口反証、残玉追尾：[条件の説明](ルールエンジン_TG04とPG04.md)。
- T06・T04・U06の入口、気配確認、追尾、部分利確、未参加補完：[条件の説明](ルールエンジン_従来手法.md)。

状態の進め方、指標計算、D07の独立担当CS04、S01の親会計と独立D07状態の継続はGoで実装しています。任意の新戦略をTOMLだけで作る仕組みではありません。新しい入力指標や状態を追加する場合はGoの変更が必要です。

手法ファイルは独立しています。例えばTG04の変更はPG04へ反映しません。D07/TG04/PG04の内部で使う旧手法の基礎候補は固定の標準条件を使用し、T06/U06ファイルの編集が別手法へ暗黙に波及しない構成です。

S01ファイルはD07共通式と3つの専用式を持ちます。S01内の独立D07も、そのS01ファイルの共通式を使います。`NK225_D07.toml`だけを編集しても、S01へ自動反映されません。

例：T04の実玉追尾を標準幅の半分にする場合、`TOPIX_T04.toml`の既存行を次へ変更します。

```toml
# 最高利益から戻す幅を標準の半分にする。
"trail.floor" = "peak - 0.5 * width * risk"
```

## 固定する部分と記録

注文・約定・建玉ID、保有上限、未約定注文の照合、場末返済、商品ON/OFFはGo側で処理します。条件式は観測値を読むだけで注文を直接送れません。除算、配列処理、外部アクセス、ユーザー関数を許可しません。

起動時に12ファイルをコンパイルし、全式のSHA256を設定の指紋へ含めます。起動記録へ`rule_documents`と`rules_hash`、各発注判断の証跡へ全体の指紋と適用手法名`rules_profile`・その指紋`active_rules_hash`を保存します。

評価に失敗した場合は待機中の判断も送信せず、当該商品の運転をエラー終了します。この異常終了では既存建玉の自動返済を保証しません。画面・台帳・口座に残る建玉と未確定注文を確認してから再起動します。通常のOFFや正常終了とは区別します。

通常ビルドは利用者が編集した実ルールを保持し、不足している手法ファイルだけを追加します。標準に戻す場合は停止中に対象TOMLを別の場所へ退避して配布物を再生成します。`settings.toml.sample`は運転設定用なので残しています。

旧`rule_engine.file`指定はD07専用の互換設定です。他手法もファイルで編集する新しい構成では`directory`を使用します。両方を同時に指定すると起動エラーになります。

Exprは式を入力型と返り値の型で事前検査できるため、今回の条件評価に採用しました。[公式の型検査説明](https://expr-lang.org/docs/configuration)。Gruleは状態更新や優先順位付きのルール連鎖も扱えますが、今回の注文状態管理はGoに残す設計です。Govaluateの元リポジトリは2025年3月25日にアーカイブされています。[公式リポジトリ](https://github.com/Knetic/govaluate)。
